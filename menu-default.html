WordPress Admin Sidebar Ôn tập kiến trúc Headless CMS cho Next.js

Tài liệu tra cứu nhanh: từng mục trong sidebar admin dùng để làm gì, và vai trò của nó thay đổi ra sao khi WordPress chuyển sang làm backend CMS cho Next.js.

碼 学
Phần 1 — Menu Items
01

Dashboard

Trang chủ của admin — cái nhìn tổng quan nhanh về tình trạng hiện tại của site: cập nhật đang chờ, site health, thống kê nhanh (posts, comments, pages), và thông báo hệ thống.

Kiểm tra mục này đầu tiên khi đăng nhập. Ở mức nâng cao, đây cũng là nơi phát hiện sớm plugin lỗi hay chứng chỉ SSL hết hạn — những thứ có thể làm gián đoạn API mà Next.js phụ thuộc vào.

02

Posts

có API

Quản lý bài viết blog, tin tức — nội dung theo trình tự thời gian, gắn tác giả. Có các mục con Add New, Categories, Tags.

FieldÝ nghĩa
titleTiêu đề hiển thị ở danh sách và trang chi tiết
contentToàn bộ nội dung, trả về dưới dạng HTML đã render
excerptĐoạn tóm tắt ngắn, dùng cho card/danh sách
slugĐịnh danh URL, ví dụ my-first-post
featured imageẢnh đại diện dùng làm thumbnail/hero
GET /wp-json/wp/v2/posts

Trong Next.js: endpoint này phục vụ trang danh sách blog, trang chi tiết bài viết, và nội dung SEO.

03

Media

có API

Thư viện chứa mọi file đã upload — hình ảnh, video, PDF — tách biệt khỏi nơi chúng được sử dụng.

  • attachment ID — mã tham chiếu để gắn ảnh vào bài viết
  • source URL — link trực tiếp đến file, dùng ngay trong <img>
  • alt text — mô tả ảnh phục vụ accessibility và SEO
GET /wp-json/wp/v2/media
04

Pages

có API

Quản lý nội dung tĩnh, độc lập: Home, About, Contact, Privacy Policy.

Posts vs. Pages: Posts theo thời gian và dùng taxonomy; Pages phân cấp, có thể có Page cha/con, không có categories.

GET /wp-json/wp/v2/pages
05

Comments

Hàng đợi quản lý bình luận: duyệt, từ chối, đánh dấu spam, hoặc xóa.

Hữu ích trên site thiên nội dung (blog, tin tức, cộng đồng). Nhiều công ty tắt hẳn trên site marketing/e-commerce để giảm khối lượng kiểm duyệt.

06

Appearance

Trong WordPress truyền thống: kiểm soát toàn bộ giao diện — theme, menu, widget, customizer, header, background.

Khi headless: phần lớn Appearance không còn liên quan vì Next.js đảm nhiệm giao diện. Mục con duy nhất vẫn hữu ích là Menus — cấu trúc điều hướng vẫn là dữ liệu có giá trị.
Sub-itemVai trò khi headless
ThemesKhông dùng — để mặc định
CustomizeKhông dùng — Next.js xử lý styling
WidgetsHầu như không dùng
MenusVẫn giữ vai trò — xem chi tiết bên dưới
Header / BackgroundKhông dùng

Menus: nơi tạo cấu trúc điều hướng độc lập với nội dung từng trang. Mục trong menu có thể lấy từ Pages, Posts, Categories, hoặc Custom Links. Kéo thả để sắp xếp; kéo lệch phải để tạo quan hệ cha/con (dropdown).

07

Plugins

Mở rộng WordPress: WooCommerce (e-commerce), SEO plugin, WPGraphQL, JWT Authentication, Cache plugin.

Mỗi plugin là code chạy với quyền admin vào database — quá nhiều plugin làm tăng rủi ro hiệu năng và bảo mật.

Khi headless: plugin mở rộng khả năng của API thay vì thay đổi giao diện — đó là toàn bộ giá trị của WPGraphQL hay JWT Authentication trong một dự án headless.

12

Next.js dùng dữ liệu WordPress

WordPress lưu dữ liệu trong MySQL → xuất qua REST API dưới dạng JSON → Next.js fetch và render.

// Lấy tất cả bài viết
fetch("https://example.com/wp-json/wp/v2/posts")

// Lấy tất cả trang
fetch("https://example.com/wp-json/wp/v2/pages")

Response mẫu:

{
  "id": 1,
  "slug": "about",
  "title": { "rendered": "About Us" },
  "content": { "rendered": "<p>...</p>" }
}

Chú ý mẫu .rendered — WordPress trả HTML sẵn, Next.js chèn cẩn thận qua dangerouslySetInnerHTML hoặc một parser phù hợp.

14

Bảo mật

  • Lộ domain WordPress là bình thường — đó là cách API truy cập được.
  • Dữ liệu API công khai (post, page, media đã xuất bản) vốn ai cũng xem được.
  • Thao tác nhạy cảm cần xác thực: phiên đăng nhập, token, đúng role/quyền.
  • Không lộ mật khẩu database, API secret, JWT secret, WooCommerce secret trong code frontend.
  • Bảo vệ wp-admin: mật khẩu mạnh, 2FA, role tối thiểu, plugin luôn cập nhật.
15

Quy trình thực tế

  • Biên tập viên đăng nhập vào admin WordPress.
  • Tạo hoặc cập nhật post, page, hoặc menu.
  • WordPress lưu thay đổi vào MySQL.
  • REST API trả nội dung dưới dạng JSON.
  • Next.js fetch JSON đó, lúc build hoặc lúc request.
  • Người dùng thấy website đã render từ dữ liệu đó.

WordPress là backend CMS quản lý nội dung; Next.js chịu toàn bộ trách nhiệm render giao diện cho người dùng cuối.
