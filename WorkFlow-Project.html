01

capstone_tailwind

Landing page tĩnh — HTML + Tailwind CSS

Tổng quan

Project là landing page/static website dùng HTML + Tailwind CSS.

Đường dẫn project: CapstoneCyper/Tailwindcss/capstone_tailwind.

Công nghệ sử dụng

HTML thuầnTailwind CSS v4 qua @tailwindcss/cliJavaScript DOM thuầnlocalStorage (theme sáng/tối)Slick carousel (assets trong lib)Không backend · không API · không Redux · không Formik/Yup

Cấu trúc xử lý chính

  • index.html: giao diện landing page.
  • src/css/input.css, src/css/output.css: Tailwind input/output.
  • src/js/index.js: xử lý tương tác UI.
  • src/html/*.html: các trang phụ như blog, docs, sign in, sign up, support, error.

Luồng theme dark/light

  1. Khi trang load, JS kiểm tra localStorage key color-theme.
  2. Nếu color-theme === "dark" hoặc chưa có key nhưng hệ thống đang prefer dark mode thì thêm class dark vào document.documentElement.
  3. Icon mặt trời/mặt trăng được bật/tắt bằng class hidden.
  4. Khi click nút #theme-toggle:
    • Toggle icon.
    • Nếu hiện tại light thì add class dark, lưu color-theme = "dark".
    • Nếu hiện tại dark thì remove class dark, lưu color-theme = "light".
  5. Tailwind dùng class dark: trong HTML để đổi màu nền, chữ, border, ảnh logo dark/light.

Luồng header khi scroll

  1. JS bắt sự kiện window.scroll.
  2. Nếu scrollY > 100:
    • Header bỏ padding lớn.
    • Thêm shadow-xl.
    • Giao diện header gọn lại khi cuộn.
  3. Nếu quay lại đầu trang:
    • Khôi phục padding ban đầu.
    • Bỏ shadow.

Luồng tab content

  1. JS lấy danh sách .tab-btn và .tab-content.
  2. Khi click tab:
    • Lấy data-tab.
    • Ẩn toàn bộ content bằng class hidden.
    • Tìm content có data-content tương ứng và remove hidden.
    • Reset trạng thái gạch chân active của tất cả tab.
    • Bật active cho tab vừa click.
  3. Có thêm nhóm .btn-content dùng chung logic data-tab / data-content.

Luồng menu mobile

  1. Nút có [data-collapse-toggle].
  2. Menu là #navbar-sticky.
  3. Khi click nút, JS toggle class hidden.
  4. Tailwind responsive class xử lý desktop/mobile.

Điểm nên nói khi phỏng vấn

  • Đây là project thiên về cắt giao diện landing page.
  • Logic chủ yếu là DOM manipulation: theme, tab, header scroll, menu mobile.
  • Tailwind giúp style nhanh bằng utility class.
  • localStorage giúp giữ trạng thái dark/light sau khi reload.
  • Không có flow nghiệp vụ như login thật, cart, CRUD backend.
02

PhoneStore_JS-HTML-TAILWINDCSS

E-commerce đa trang — HTML + Tailwind + JavaScript thuần

Tổng quan

Project là website bán điện thoại dùng HTML + Tailwind + JavaScript thuần.

Công nghệ sử dụng

HTML nhiều trangTailwind CSSJavaScript ES modulesAxios + fetch gọi MockAPIlocalStorage (user, login, cart, wishlist, order, brand)xlsx (xuất Excel)Không React · không Redux · không Formik/YupValidate bằng regex + JS thủ công

Cấu trúc chính — User

  • src/js/userJS/core.js: khai báo API, DOM element, state chung, localStorage key.
  • login.js: đăng nhập user/admin.
  • register.js: đăng ký user.
  • product-flow.js: lấy sản phẩm, render danh sách, phân trang, chọn option mua hàng.
  • cart-flow.js: giỏ hàng, tăng/giảm/xóa, chọn sản phẩm thanh toán.
  • checkout-flow.js: đặt hàng.
  • order-flow.js, order-check-flow.js: lưu và kiểm tra đơn hàng.
  • filter-flow.js: search/filter/sort.
  • wishlist-popup.js: yêu thích.
  • review-flow.js, return-flow.js: đánh giá, đổi trả.

Cấu trúc chính — Admin

  • src/js/adminJS/core.js: API, DOM admin, state admin.
  • crud-flow.js: CRUD sản phẩm.
  • order-flow.js, order-detail-flow.js: quản lý đơn hàng.
  • user-flow.js: quản lý user.
  • dashboard-flow.js: thống kê.
  • review-flow.js, return-flow.js: quản lý đánh giá, đổi trả.
  • profile-flow.js: đổi mật khẩu admin.

Dữ liệu lưu ở đâu

  • API sản phẩm: https://69f8c3e5f7044aa0103e73e0.mockapi.io/api/v1/productphone
  • User: HiKuPHONE_USERS
  • Admin mặc định: HiKuPHONE_ADMIN
  • Trạng thái login: isLoggedIn, username, role
  • Cart theo user: GIO_HANG_USER_${username}
  • Wishlist theo user: WISHLIST_USER_${username}
  • Brand: HiKuPHONE_BRANDS
  • Sản phẩm được chọn checkout: KP_CHECKOUT_SELECTED_CART_ITEMS
  • Orders lưu localStorage qua order-flow.

Luồng đăng ký

  1. User nhập phone, email, username, password.
  2. File register.js bắt submit form.
  3. Validate thủ công:
    • Phone regex: 10 chữ số.
    • Email regex chuẩn email.
    • Password regex: có chữ thường, chữ hoa, số, ký tự đặc biệt, tối thiểu 6 ký tự.
    • Không được bỏ trống.
  4. Kiểm tra trùng username và email trong state.users.
  5. Nếu hợp lệ:
    • Push user mới vào state.users.
    • User gồm id, username, password, phone, email, role user, status active, createdAt.
    • Gọi luuUsers() để lưu vào localStorage key HiKuPHONE_USERS.
  6. Alert thành công và chuyển sang login.html.

Luồng đăng nhập

  1. User nhập username/password.
  2. login.js validate:
    • Không để trống.
    • Password phải đúng regex.
  3. Kiểm tra admin trước:
    • Nếu localStorage chưa có admin thì tạo admin mặc định username admin, password Admin123@.
    • Nếu khớp admin: set isLoggedIn = true, username = admin, role = admin, chuyển sang page-admin/dashboard.html.
  4. Nếu không phải admin:
    • Lấy danh sách HiKuPHONE_USERS.
    • Tìm user khớp username/password.
    • Nếu không có, báo tài khoản chưa đăng ký.
    • Nếu user status locked, báo tài khoản bị khóa.
    • Nếu hợp lệ: set isLoggedIn = true, username, role = user, chuyển về index.html.
  5. Có login Google/Facebook demo:
    • set login state vào localStorage.
    • username là "Google User" hoặc "Facebook User".
    • role user.

Luồng lấy và hiển thị sản phẩm

  1. product-flow.js gọi axios.get(API).
  2. Dữ liệu trả về lưu vào state.danhSachSP và state.activeList.
  3. Render danh sách bằng renderDanhSachSP(list).
  4. Hàm render:
    • Tính phân trang theo state.currentPage, itemsPerPage = 8.
    • Render card sản phẩm bằng template string.
    • Hiển thị giá, giá cũ, giảm giá, trả góp, rating, quà tặng, trạng thái hết hàng.
    • Nút Mua và Thêm giỏ mở popup chọn option.
  5. Nếu API lỗi thì hiện lỗi kết nối API.
  6. Badge giỏ hàng được cập nhật bằng capNhatSoLuongGioHang().

Luồng search / filter / sort / phân trang

  1. Dữ liệu gốc nằm trong state.danhSachSP.
  2. Khi search/filter/sort:
    • Lọc theo keyword, hãng/type, giá hoặc điều kiện tương ứng.
    • Gán kết quả vào active list.
    • Reset currentPage = 1.
    • Render lại danh sách.
  3. Phân trang:
    • changePage(page) đổi state.currentPage.
    • Gọi lại renderDanhSachSP(state.activeList).
    • Scroll về section sản phẩm.

Luồng chọn option mua hàng / thêm giỏ

  1. Khi click Mua hoặc Thêm giỏ:
    • Gọi openProductOptionPopup(id, action).
    • Tìm product trong state.danhSachSP.
    • Reset quantity, selectedCapacity, selectedColor.
    • Hiển thị popup.
  2. Trong popup:
    • User chọn dung lượng.
    • User chọn màu sắc.
    • User tăng/giảm số lượng.
    • Số lượng không được vượt tồn kho.
  3. Submit popup:
    • Validate phải chọn dung lượng và màu.
    • Kiểm tra isLoggedIn.
    • Nếu chưa login thì mở popup yêu cầu đăng nhập.
  4. Nếu action là buy: redirect sang checkout.html kèm query id, quantity, capacity, color.
  5. Nếu action là cart:
    • Tạo cartId = productId_capacity_color.
    • Nếu item đã có trong giỏ thì cộng số lượng.
    • Nếu chưa có thì push vào state.gioHang.
    • Lưu localStorage theo key GIO_HANG_USER_${username}.
    • Cập nhật badge và hiện toast.

Luồng giỏ hàng

  1. Cart được load từ localStorage theo user hiện tại.
  2. Mở cart popup bằng renderGioHang().
  3. Mỗi item có id/cartId, name, image, price, selectedCapacity, selectedColor, soLuong.
  4. User có thể:
    • Tick chọn từng sản phẩm.
    • Chọn tất cả.
    • Xóa sản phẩm đã chọn.
    • Tăng/giảm số lượng.
    • Xóa từng sản phẩm.
  5. Khi tăng số lượng:
    • Gọi fetch API sản phẩm theo id.
    • Kiểm tra tồn kho hiện tại.
    • Nếu vượt tồn kho thì alert.
    • Nếu hợp lệ thì tăng, lưu localStorage và render lại.
  6. Khi thanh toán từ giỏ:
    • Kiểm tra giỏ không rỗng.
    • Kiểm tra đã tick ít nhất một sản phẩm.
    • Fetch toàn bộ API sản phẩm.
    • So sánh tồn kho từng sản phẩm được chọn.
    • Lưu selected cart ids vào KP_CHECKOUT_SELECTED_CART_ITEMS.
    • Redirect sang checkout.html?from=cart.

Luồng checkout

  1. checkout-flow.js xác định nguồn checkout:
    • Nếu from=cart: lấy cart theo user và lọc các item đã chọn.
    • Nếu có id: fetch sản phẩm theo id, lấy option từ query.
    • Nếu không có gì: lấy toàn bộ cart hiện tại.
  2. Render order summary: danh sách sản phẩm, giá, số lượng, dung lượng, màu, quà tặng nếu có, tổng tiền.
  3. Validate form:
    • Họ tên không trống.
    • SĐT regex 10 số.
    • Email đúng định dạng.
    • Nếu giao hàng tận nơi thì bắt buộc province, district, address.
    • Phải có sản phẩm checkout.
  4. Trước khi đặt hàng: fetch API sản phẩm, kiểm tra tồn kho từng item.
  5. Tạo order gồm: id (createOrderId()), customer info, receiveMethod (nhận tại cửa hàng / giao tận nơi), địa chỉ hoặc store, paymentMethod, items, total, status "Đang xử lý", stockStatus "Chưa trừ kho", createdAt.
  6. Lưu order vào localStorage.
  7. Nếu checkout từ cart: xóa các sản phẩm đã chọn khỏi cart, remove KP_CHECKOUT_SELECTED_CART_ITEMS.
  8. Alert đặt hàng thành công và chuyển sang order-check.html.

Luồng admin CRUD sản phẩm

  1. Admin vào trang manage-product.
  2. crud-flow.js gọi fetchDanhSachSP().
  3. Fetch bằng axios.get(API_URL).
  4. Lưu vào state.danhSachSP, render table.
  5. Thêm sản phẩm:
    • Validate form thủ công trong ui-flow.
    • Lấy dữ liệu bằng getProductDataFromForm().
    • axios.post(API_URL).
    • Tạo review mặc định 5 sao.
    • Reset form, fetch lại danh sách.
  6. Sửa sản phẩm:
    • Click editProduct(id).
    • Tìm product trong state, đổ dữ liệu lên form.
    • Ẩn nút thêm, hiện nút update.
    • Click update gọi axios.put(API_URL/id).
    • Fetch lại.
  7. Xóa sản phẩm:
    • Confirm bằng shared-dialog.
    • axios.delete(API_URL/id).
    • Fetch lại.
  8. Admin có quản lý hãng: brand lưu localStorage key HiKuPHONE_BRANDS, có default brand iPhone, Samsung, OPPO, Vivo, Realme, Asus, Nokia.

Luồng admin / user / order khác

  • Admin dashboard đọc sản phẩm, đơn hàng, user để thống kê.
  • Admin quản lý user: khóa/mở khóa tài khoản.
  • Admin quản lý order: xem chi tiết, cập nhật trạng thái, hủy đơn.
  • User order-check đọc order trong localStorage để xem lịch sử, hủy đơn.
  • Review/return flow lưu thông tin đánh giá và đổi trả vào dữ liệu sản phẩm/đơn hàng.

Điểm nên nói khi phỏng vấn

  • Đây là SPA giả lập bằng nhiều file HTML, không dùng framework.
  • State được quản lý bằng object state trong JS module.
  • Dữ liệu lâu dài dùng localStorage.
  • Sản phẩm lấy từ MockAPI bằng axios/fetch.
  • Validate bằng regex thủ công.
  • Cart tách theo từng user bằng key localStorage có username.
  • Admin CRUD thao tác trực tiếp với MockAPI.
03

ShoesStore_ReactJS

React + Vite — Redux Toolkit, React Query, Formik/Yup

Tổng quan

Project là web bán giày bằng React + Vite.

Công nghệ sử dụng

React · ViteReact Router DOMRedux Toolkit + React ReduxTanStack React QueryAxiosFormik + YupTailwind CSSlocalStoragexlsxEmbla Carousel

Cấu trúc chính

  • src/App.jsx: khai báo routes, layout, load cart/order theo user, global alert/confirm/cart popup.
  • src/main.jsx: mount app.
  • src/redux/store.js: configureStore.
  • src/redux/slices/authSlice.js, cartSlice.js, orderSlice.js, reviewSlice.js, giftSlice.js.
  • src/api/axiosClient.js, productApi.js: API product.
  • src/hooks/useProductsQuery.js, useProductQuery.js: lấy sản phẩm bằng React Query.
  • src/hooks/useProductMutations.js: thêm/sửa/xóa/update stock bằng mutation.
  • pages-auth: Login, Register, ForgotPassword, ResetPassword.
  • pages-user: Home, Products, ProductDetail, Checkout, OrderCheck, Policy, Promotions.
  • pages-admin: Dashboard, ManageProducts, ManageOrders, ManageCustomers, ManageReviews, ManageGifts.

Store Redux

  • cartStore: cartReducer
  • authStore: authReducer
  • orderStore: orderReducer
  • reviewStore: reviewReducer
  • giftStore: giftReducer

Routing

Auth: /login · /register · /forgot-password · /reset-password

UserLayout: / · /products · /products/:id/:alias · /promotions · /policy · /policy/:type · /checkout (ProtectedRoute) · /order-check (ProtectedRoute)

Admin: /admin (AdminRoute) · /admin/products · /admin/orders · /admin/orders/:id · /admin/customers · /admin/profile · /admin/reviews · /admin/reviews/:productId · /admin/gifts

Not found: route * render 404.

Luồng auth / login

  1. Login.jsx dùng Formik quản lý form username/password.
  2. Yup validate: username required, password required.
  3. Khi submit:
    • Lấy admin account từ localStorage key HiKushoes_admin_account, fallback admin mặc định (username admin, password Admin123@, role admin).
    • Nếu khớp admin: dispatch loginSuccess(adminUser), authSlice lưu user vào Redux state, localStorage set HiKushoes_user, navigate /admin.
  4. Nếu không phải admin:
    • Tìm user bằng findUserByUsername.
    • Nếu không có: setFieldError username.
    • Nếu sai password: setFieldError password.
    • Nếu user bị locked: báo lỗi.
    • Nếu hợp lệ: dispatch loginSuccess(user), lưu vào localStorage HiKushoes_user, navigate /.
  5. authSlice:
    • initialState đọc user từ localStorage.
    • loginSuccess set state.user và localStorage.
    • logout clear state.user và remove localStorage.

Luồng register

  1. Register.jsx dùng Formik.
  2. Yup validate:
    • username required.
    • email đúng định dạng và required.
    • phone đúng 10 số và required.
    • password tối thiểu 6 ký tự, có chữ thường, chữ hoa, số, ký tự đặc biệt.
    • confirmPassword phải trùng password.
  3. Submit:
    • Kiểm tra trùng username/email/phone bằng userStorage.
    • Nếu trùng thì setFieldError.
    • Nếu hợp lệ thì addUser vào localStorage.
    • User gồm id, username, email, phone, password, role user, status active, createdAt.
    • Alert thành công và navigate /login.

Luồng route guard

ProtectedRoute:

  1. Đọc HiKushoes_user từ localStorage.
  2. Nếu chưa login thì Navigate về /.
  3. Nếu có user thì render children.

AdminRoute:

  1. Đọc HiKushoes_user.
  2. Nếu chưa login thì Navigate /.
  3. Nếu role khác admin thì Navigate /.
  4. Nếu role admin thì render admin layout.

Luồng load data trong App.jsx

  1. App lấy user từ Redux authStore.user.
  2. Lấy cart từ Redux cartStore.cart.
  3. Gọi useProductsQuery() để lấy toàn bộ sản phẩm từ API.
  4. Lọc product chưa deleted.
  5. useEffect theo user:
    • Nếu chưa login: dispatch loadCartByUser(null), dispatch loadOrdersByUser(null).
    • Nếu đã login: dispatch loadCartByUser(user.username); nếu admin dispatch loadAllOrdersForAdmin(), nếu user dispatch loadOrdersByUser(user.username).
  6. App override window.alert thành toast alert custom.
  7. App register confirm dialog custom qua registerConfirmHandler.
  8. Cart popup dùng Redux action tăng/giảm/xóa.

Luồng lấy sản phẩm

  1. productApi gọi axiosClient: getAll GET /shoes, getById GET /shoes/:id, create POST /shoes, update PUT /shoes/:id, remove DELETE /shoes/:id.
  2. useProductsQuery dùng TanStack Query:
    • queryKey ['products'].
    • queryFn gọi productApi.getAll().
    • Normalize data: convert price, salePrice, oldPrice, discount, quantity về number; đảm bảo colors/sizes/reviews là array; set deleted, feature, hasGift boolean; tính rating/totalReviews.
  3. useProductQuery lấy chi tiết theo id.
  4. React Query cache data và tự quản lý loading/error.
  5. useProductMutations dùng useMutation: addProductMutation, updateProductMutation, deleteProductMutation, decreaseStockMutation, increaseStockMutation — sau mutation gọi invalidateQueries để refetch products.

Luồng danh sách sản phẩm

  1. Trang Products nhận products từ App.
  2. Dùng hook filter/sort để lọc theo keyword, brand, gender, giá, loại giày, khuyến mãi...
  3. Render bằng ProductList/ProductCard.
  4. Click card đi tới /products/:id/:alias.

Luồng chi tiết sản phẩm

  1. ProductDetail lấy id, alias từ useParams.
  2. Gọi useProductQuery(id) và useProductsQuery().
  3. Tìm product: ưu tiên product detail từ API, nếu không có thì fallback trong list theo id/alias.
  4. State nội bộ: selectedColorId, mainImage, avtImage, selectedSize, sizeError, buyQuantity, selectedGiftId, isLoginPopupOpen, zoom/album state.
  5. Khi product thay đổi: set màu đầu tiên, set ảnh chính, reset size, quantity, gift.
  6. User chọn màu: set selectedColorId, đổi ảnh chính theo màu.
  7. User chọn size: kiểm tra size có trong product.sizes, nếu không có thì báo lỗi size hết.
  8. User tăng/giảm quantity: tối thiểu 1, tối đa bằng product.quantity.
  9. Trước khi add cart/buy now: nếu chưa login mở LoginModal, nếu hết hàng báo lỗi, nếu chưa chọn size báo lỗi.
  10. Add cart: tạo cart product gồm product, selectedColor, selectedSize, cartQuantity, selectedGift, price sale; dispatch addToCart; alert thành công.
  11. Buy now: navigate /checkout và truyền state checkoutItems: [cartProduct], checkoutType: BUY_NOW, selectedGift.

Luồng cart Redux

  1. cartSlice lưu cart theo từng user bằng key HiKuShoesCart_${username}, guest dùng HiKuShoesCart_guest.
  2. loadCartByUser: nhận username, đọc localStorage tương ứng, gán vào state.cart.
  3. addToCart: tạo key item id-selectedSize-selectedColorId; nếu item đã có thì cộng cartQuantity, nếu chưa có thì push item; lưu localStorage.
  4. increaseCartItem: tìm item theo key, tăng cartQuantity, lưu localStorage.
  5. decreaseCartItem: giảm cartQuantity, nếu quantity <= 0 thì remove, lưu localStorage.
  6. removeCartItem: xóa khỏi cart, lưu localStorage.
  7. clearCart: clear state.cart, remove localStorage key cart hiện tại.

Luồng checkout

  1. Checkout page được bọc ProtectedRoute nên cần login.
  2. Nguồn checkout: nếu Buy Now lấy location.state.checkoutItems, nếu từ cart lấy prop cart từ Redux.
  3. Formik quản lý form checkout.
  4. Yup validate:
    • fullName required.
    • phone bắt đầu 03/05/07/08/09 và đủ 10 số.
    • email required + đúng định dạng.
    • Nếu receiveMethod là store thì store required.
    • Nếu receiveMethod là delivery thì province, district, address required.
  5. Trước submit:
    • Nếu chưa user thì alert và navigate login.
    • Nếu product đang loading thì chặn.
    • Kiểm tra tồn kho bằng data từ useProductsQuery: product không tồn tại, product deleted, quantity <= 0, quantity nhỏ hơn số lượng trong cart.
  6. Tạo order gồm id (Date.now()), orderCode (generateOrderCode()), ownerUsername, customer info, receiveMethod, deliveryInfo, paymentMethod, note, products checkoutItems, selectedGift/gift, totalPrice, status "Đang xử lý", stockStatus "Chưa trừ kho", createdAt, createdAtISO.
  7. dispatch addOrder(newOrder).
  8. Nếu checkout từ cart: dispatch removeCartItem từng sản phẩm đã checkout.
  9. Alert đặt hàng thành công.
  10. Navigate /order-check.

Luồng order Redux

  1. orderSlice lưu order theo user với prefix HiKushoes_orders_, key HiKushoes_orders_${username}.
  2. loadOrdersByUser: đọc order từ localStorage theo username.
  3. loadAllOrdersForAdmin: duyệt toàn bộ localStorage, lấy key bắt đầu bằng HiKushoes_orders_, gộp tất cả order và sort mới nhất.
  4. addOrder: normalize products, stockStatus mặc định "Chưa trừ kho", unshift order vào state, lưu localStorage.
  5. updateOrderStatus: admin/user cập nhật status; nếu status "Đã giao hàng" và chưa record sold stats thì tăng sold stats trong HiKushoes_sold_stats; nếu hủy thì lưu cancelReason, cancelBy, cancelAt.
  6. cancelOrderByCustomer: user tự hủy order, status "Đã bị hủy".
  7. requestReturnProduct: user gửi yêu cầu đổi trả cho từng product trong order, lưu reason, files, status "Chờ duyệt", refundStatus.
  8. updateProductReturnRequest: admin duyệt/từ chối đổi trả; nếu đã giao hàng, đổi trả được chấp nhận và đã hoàn tiền thì giảm sold stats.
  9. deleteOrder: nếu admin xóa thì tìm owner và xóa ở localStorage của user đó; nếu user xóa thì xóa trong order của chính user.

Luồng admin quản lý sản phẩm

  1. Admin vào /admin/products, được AdminRoute bảo vệ.
  2. Trang dùng React Query lấy products.
  3. Form thêm/sửa sản phẩm dùng state/Formik tùy component.
  4. Khi thêm: gọi addProductMutation, productApi.create POST /shoes, invalidate query ['products'].
  5. Khi sửa: gọi updateProductMutation, PUT /shoes/:id, invalidate list và detail query.
  6. Khi xóa: gọi deleteProductMutation, DELETE /shoes/:id, remove detail query và invalidate list.
  7. Khi cập nhật tồn kho: decreaseStockMutation hoặc increaseStockMutation, PUT sản phẩm với quantity mới.

Luồng admin quản lý đơn hàng

  1. Admin login role admin.
  2. App dispatch loadAllOrdersForAdmin.
  3. Admin thấy toàn bộ order từ mọi user.
  4. Khi cập nhật trạng thái: dispatch updateOrderStatus, orderSlice tìm ownerUsername, cập nhật order trong localStorage của user sở hữu, reload lại danh sách admin.
  5. Stock không trừ ngay khi user đặt hàng.
  6. Logic ghi chú trong Checkout: kho chỉ trừ khi admin chuyển đơn sang "Đang giao hàng" hoặc "Đã giao hàng".

Luồng review / gift

  • giftSlice quản lý danh sách quà tặng.
  • ProductDetail nếu product.hasGift thì cho chọn quà.
  • selectedGift được gắn vào cart product hoặc order.
  • reviewSlice/ProductReviews quản lý đánh giá sản phẩm.
  • Admin có ManageReviews và ReviewDetail để quản lý review theo product.

Điểm nên nói khi phỏng vấn

  • Project React có kiến trúc rõ hơn PhoneStore: React Router quản lý route, Redux Toolkit quản lý auth/cart/order/review/gift, React Query quản lý server state sản phẩm, Formik/Yup quản lý form và validate, Axios gọi API, localStorage persist user/cart/order.
  • Phân biệt rõ: server state (products từ API → React Query), client state (cart/auth/order → Redux), persistent local state (localStorage).
  • Route guard bảo vệ checkout/admin.
  • Cart và order được tách theo username.
  • Admin có quyền xem tất cả order bằng cách duyệt localStorage theo prefix.
